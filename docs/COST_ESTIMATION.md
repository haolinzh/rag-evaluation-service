# 成本估算与模型选型说明

本文档说明本项目在阿里云百炼（DashScope）上三个模型选型的理由，并给出单次问答与月度运行的成本估算方法。

> ⚠️ 价格会随地域（北京/新加坡）、促销活动、上下文长度档位浮动，且不同计费页口径不一。下表为**非促销目录价**的保守估算，用于量级判断；上线前请以[阿里云百炼官方定价页](https://www.alibabacloud.com/help/zh/model-studio/model-pricing)为准。

---

## 1. 模型选型理由

| 用途 | 模型 | 选型理由 |
|---|---|---|
| 对话生成 | `qwen-plus` | 中英双语、通用能力与成本平衡点；比 `qwen-max` 便宜一个数量级，足以胜任知识库问答与合规话术 |
| 向量化 | `text-embedding-v3` | 原生多语言（中英混排语料无需翻译），1024 维，召回质量与维度成本的平衡 |
| 精排 | `qwen3-rerank` | 对候选集（≤20 条）做相关性精排，按输入 token 计费、单价极低，是混合检索的增量成本点 |

**为什么不用 `qwen-max` / `qwen3-max`**：本场景答案严格限定在检索到的知识库上下文内，不依赖长文本推理与复杂多步逻辑，`qwen-plus` 的生成质量已经满足合规与忠实度要求；高等级模型带来的 token 单价数倍上升，边际收益低。

**为什么精排做成独立开关**（`retrieval.rerank-enabled`）：精排是唯一「每个请求都额外多一次 API 调用」的环节，单价比 embedding 高、且与 topK 无关地吃候选集 token。在低预算或配额紧张时可直接关闭，退化为纯 RRF，不影响可用性。

## 3. 单次问答成本估算

假设一次典型请求（`hybrid-rerank` 模式，topK=5，rerank-candidates=20）：

| 环节 | token 用量（估算） | 单价 | 成本 |
|---|---|---|---|
| Query 向量化 | ~20 input token | ¥0.0005/千 | ¥0.00001 |
| 候选精排 | 20 chunk × ~500 token ≈ 10,000 input token | ¥0.0009/千 | ¥0.009 |
| 生成 prompt（上下文 + 历史 + 系统提示） | ~3,000 input token | ¥0.004/千 | ¥0.012 |
| 生成 answer | ~400 output token | ¥0.012/千 | ¥0.0048 |
| **合计** | | | **≈ ¥0.026** |

即**单次完整问答约 0.02~0.03 元**（促销价下约 0.005 元）。缓存命中（语义缓存）时跳过生成与精排，成本趋近于零（仅 query 向量化）。

## 4. 月度成本估算

按 `日活 100 人 × 每人 20 问 = 2000 问/天`，缓存命中率 40%：

| 项目 | 计算 | 月成本 |
|---|---|---|
| 未命中生成（60% × 2000 = 1200 次/天） | 1200 × ¥0.026 × 30 | ≈ ¥936 |
| 命中缓存（800 次/天） | 800 × ¥0.00001 × 30 | ≈ ¥0.24 |
| 首次入库 embedding（10 万 chunk × 500 token） | 5 千万 token × ¥0.0005/千 | ≈ ¥25（一次性） |
| **合计（不含入库）** | | **≈ ¥940/月** |

即当前量级下，**月度 API 成本约数百元到一千元**，远低于自建 GPU 推理的硬件成本。

---

## 5. 成本优化建议

1. **语义缓存**（已实现）：归一化问题命中后直接返回，跳过生成与精排，是成本最大的杠杆。
2. **`rerank-enabled=false`**：预算紧张时关闭精排，单次成本下降约 ¥0.009（约 1/3）。
3. **降低 `rerank-candidates`**：从 20 降到 10，精排 token 减半。
4. **降低 `recall-size-multiplier` 与 `top-k`**：缩小上下文与候选集，减少 prompt token。
5. **短上下文历史**（`history.limit=10`）：控制注入历史轮数，减少 prompt token。
