# 成本估算与模型选型说明

本文档说明本项目在阿里云百炼（DashScope）上的模型选型理由，按 case study 要求给出 **quality（质量）/ cost（成本）/ latency（延迟）** 三个维度的显式权衡，并提供 **每 1000 次调用的 token 成本估算**。

> ⚠️ 价格会随地域（北京/新加坡）、促销活动、上下文长度档位浮动，不同计费页口径不一。下表为**非促销目录价**的保守估算，用于量级判断；上线前请以[阿里云百炼官方定价页](https://www.alibabacloud.com/help/zh/model-studio/model-pricing)为准。延迟数据为**本项目实测**（见 §2），会随网络、模型版本、并发负载波动。

---

## 1. 模型选型：quality / cost / latency 三维权衡

### 1.1 对话模型对比（核心权衡点）

| 模型 | 定位 | 质量 | 目录价（输入/输出，每百万 token） | 单请求 p90 | 5 并发 p90 | 结论 |
|---|---|---|---|---|---|---|
| `qwen-turbo` | 轻量快速 | 中 | ¥2 / ¥6 | ~6.2s | **4.8s ✅** | 高并发/低成本默认 |
| `qwen-plus` | 通用平衡 | 中高 | ¥4 / ¥12 | ~12.0s | — | 质量优先的折中 |
| `qwen-max` | 旗舰 | 高 | ¥20 / ¥60 | ~9.4s | **16.9s ❌** | 低并发高质量 |
| `deepseek-r1` | 深度思考 | 高（推理链） | 输出含思考 token，显著更贵 | ~26.6s | — | 复杂推理，不用于常规问答 |

**关键结论（实测驱动）**：`qwen-max` 单请求 p90 尚能卡进 10s（9.4s），但**并发下严重恶化**——5 并发时 p90 飙到 16.9s，39% 的请求超 10s，吞吐仅 0.44 req/s（DashScope 对旗舰模型的并发推理资源受限/排队）。而 `qwen-turbo` 单请求快、**并发扩展性好**（5 并发 p90 仍 4.8s，0% 超 10s，吞吐 1.53 req/s，约为 max 的 3.5 倍）。

因此，在「90% 请求 10s 内 + ≥5 并发」的硬性 NFR 下，**对话默认模型选定 `qwen-turbo`**（原默认 `qwen-plus` 单请求即超 10s，`qwen-max` 并发下也不达标）。

### 1.2 其余模型选型

| 用途 | 模型 | 选型理由 |
|---|---|---|
| 向量化 | `text-embedding-v3` | 原生多语言（中英混排语料无需翻译），1024 维，召回质量与维度成本的平衡；仅输入计费、单价极低 |
| 精排 | `qwen3-rerank` | 对候选集（≤20 条）做相关性精排，按输入 token 计费、单价极低，是混合检索唯一的增量成本点 |

**精排按需启用**（由检索模式控制）：只有 `hybrid-rerank` 模式才调用精排，`hybrid`/`vector` 退化为纯 RRF/纯向量，不影响可用性。

## 2. Latency 实测（含并发）

### 2.1 单请求延迟（`request_log` 历史，526 个成功请求）

| 指标 | 值 | 对照 10s 目标 |
|---|---|---|
| p50 | 4.2s | ✅ |
| p90 | 10.7s | ❌ 超 0.7s |
| p95 | 13.0s | ❌ |

按模型拆 p90：`qwen-turbo` 6.2s、`qwen-max` 9.4s、`qwen-plus` 12.0s、`deepseek-r1` 26.6s。**瓶颈在 LLM 生成**（生成占绝对大头），检索侧（ES + pgvector + rerank）均值仅 246~780ms，不是瓶颈。

### 2.2 5 并发压测（20 请求/模型，`hybrid-rerank`，清缓存，区分拒答）

| 模型 | p50 | p90 | p95 | 超 10s 占比 | 吞吐 |
|---|---|---|---|---|---|
| `qwen-turbo` | 3.1s | **4.8s** ✅ | 5.3s | 0% | 1.53 req/s |
| `qwen-max` | 9.3s | **16.9s** ❌ | 20.8s | 39% | 0.44 req/s |

> 压测方法：Python `ThreadPoolExecutor(max_workers=5)` 并发打 `/api/chat`，20 个互不相同的问题（避免语义缓存命中），压测前清缓存，统计时排除拒答（refusal）请求。错误率均为 0%。

### 2.3 结论

- 单请求下 qwen-max 勉强达标（9.4s），但并发下翻倍恶化 → **不满足 NFR**。
- qwen-turbo 单请求与并发下均轻松达标，且吞吐约 3.5 倍 → **满足 NFR 的默认选择**。

## 4. 每 1000 次调用成本（需求口径）

假设一次典型请求（`hybrid-rerank` 模式，topK=5，rerank-candidates=20，prompt ~3,000 input token、answer ~400 output token）：

| 环节 | token 用量（估算） | 单价 | 成本（与对话模型无关的固定部分） |
|---|---|---|---|
| Query 向量化 | ~20 input token | ¥0.0005/千 | ¥0.00001 |
| 候选精排 | 20 chunk × ~500 token ≈ 10,000 input token | ¥0.0009/千 | ¥0.009 |
| **固定部分小计** | | | **≈ ¥0.009** |

生成部分随对话模型变化：

| 对话模型 | 生成成本（3000 in + 400 out） | 单次完整问答 | **每 1000 次（未命中缓存）** |
|---|---|---|---|
| `qwen-turbo` | ¥0.006 + ¥0.0024 = ¥0.0084 | ≈ ¥0.017 | **≈ ¥17** |
| `qwen-plus` | ¥0.012 + ¥0.0048 = ¥0.0168 | ≈ ¥0.026 | **≈ ¥26** |
| `qwen-max` | ¥0.06 + ¥0.024 = ¥0.084 | ≈ ¥0.093 | **≈ ¥93** |

缓存命中（语义缓存）时跳过生成与精排，单次成本趋近于零（仅 query 向量化 ¥0.00001）。

### 缓存命中下的每 1000 次成本

| 对话模型 | 命中率 0%（最坏） | 命中率 40%（典型） |
|---|---|---|
| `qwen-turbo` | ¥17 | ¥10.2 |
| `qwen-plus` | ¥26 | ¥15.6 |
| `qwen-max` | ¥93 | ¥55.8 |

## 5. 选型结论

| 场景 | 推荐模型 | 理由 |
|---|---|---|
| **默认对话（满足 10s/5 并发 NFR）** | `qwen-turbo` | 并发 p90 4.8s、吞吐 3.5×，成本仅为 max 的 1/5，本场景知识库问答对生成质量要求中即可满足 |
| 高质量 / 低并发 | `qwen-plus` 或 `qwen-max` | 单请求质量更高，但需接受并发延迟恶化与成本上升 |
| 深度推理（分析题、复杂逻辑） | `deepseek-r1` / thinking 模型 | 推理链质量高，但延迟 ~26s 且成本高，仅按需用于非实时场景 |

**一句话权衡**：`qwen-turbo` 以可接受的质量换取 **3.5 倍吞吐 + 1/5 成本 + 并发下稳定达标**，是满足本 case study 硬性 NFR 的正确默认；`qwen-max` 是「质量优先、牺牲延迟与成本」的选择，仅适合低并发高质量场景。

---

## 6. 成本优化建议

1. **语义缓存**（已实现）：归一化问题命中后直接返回，跳过生成与精排，是成本最大的杠杆。
2. **默认 `qwen-turbo`**：比 `qwen-max` 单次成本低 5 倍以上。
3. **切换 `hybrid` 模式（不精排）**：预算紧张时关闭精排，单次成本下降约 ¥0.009（约 1/3）。
4. **降低 `rerank-candidates`**：从 20 降到 10，精排 token 减半。
5. **降低 `recall-size-multiplier` 与 `top-k`**：缩小上下文与候选集，减少 prompt token。
6. **短上下文历史**（`history.limit=10`）：控制注入历史轮数，减少 prompt token。

## 7. 月度成本估算（量级参考）

按 `日活 100 人 × 每人 20 问 = 2000 问/天`，缓存命中率 40%，默认 `qwen-turbo`：

| 项目 | 计算 | 月成本 |
|---|---|---|
| 未命中生成（60% × 2000 = 1200 次/天） | 1200 × ¥0.017 × 30 | ≈ ¥612 |
| 命中缓存（800 次/天） | 800 × ¥0.00001 × 30 | ≈ ¥0.24 |
| 首次入库 embedding（10 万 chunk × 500 token） | 5 千万 token × ¥0.0005/千 | ≈ ¥25（一次性） |
| **合计（不含入库）** | | **≈ ¥610/月** |

即默认 `qwen-turbo` 下月度 API 成本约 **600~700 元**（`qwen-plus` 约 940 元，`qwen-max` 约 3360 元），远低于自建 GPU 推理的硬件成本。
